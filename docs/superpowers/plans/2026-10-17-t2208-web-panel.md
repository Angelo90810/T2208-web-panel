# T2208 Web Control Panel Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Phase 1 of the local-first T2208 panel as an interactive, feature-complete simulated web UI with no hardware control.

**Architecture:** A single React SPA consumes one typed `MixerAdapter` interface. Phase 1 implements only `DemoAdapter`, with in-browser preset/scene persistence. A future local bridge is not implemented here; UI modules must not depend on raw TCP/UDP or device packet formats.

**Tech Stack:** Proposed: Node.js 24.19.0 / npm 11.17.0; Vite, React, TypeScript; custom CSS variables and SVG controls (no UI kit); Vitest + React Testing Library; Playwright for responsive acceptance tests.

**Spec:** `docs/superpowers/specs/2026-10-17-t2208-web-panel-design.md`

## Global Constraints

- Phase 1 is **DEMO only**: no device discovery, network scans, UDP/TCP, bridge, firmware writes, or real mixer commands.
- Show an explicit DEMO state on every view; never represent simulated state as a real connection or applied hardware change.
- Keep feature coverage across desktop, tablet, and phone; adapt layout, not capabilities.
- The default UI language is Brazilian Portuguese.
- The simulated preset/scene library may persist in browser-local storage; never write to the APK/EXE or hardware.
- Do not modify, install, or execute the supplied APK or EXE.
- Exact channel/DCA/bus/digital-card counts remain unverified; drive layouts from capabilities and label demo values as simulated.
- Confirm 48V, factory/default reset, preset deletion, and scene recall; cancelling must not change simulated state.
- The local bridge, authentication/pairing, IGMP/multicast, and real protocol behavior are out of scope until hardware validation.
- Do not expose the demo or future bridge on the public internet; real integration remains local-network-only unless a separate security design is approved.

## Review Focus

- Malformed or absent `localStorage` library → seed a valid demo library without crashing; pin with `usesSeedWhenStoredLibraryIsAbsent` and `fallsBackToSeedWhenStoredLibraryIsInvalid` in Task 2.
- Non-default channel/DCA/bus counts and the DCA6-vs-DCA12 evidence mismatch → render from capabilities without truncation; pin with `adaptsToInjectedCapabilities`, `rendersChannelBankFromCapabilities`, and `rendersDcaGroupsFromCapabilities` in Tasks 2, 4, and 6.
- Cancelled 48V, AutoMix clear, preset deletion, scene recall, or factory reset → dispatch no state change; pin with `cancelledPhantomPowerDoesNotDispatch`, `cancelledAutoMixClearDoesNotDispatch`, `cancelledPresetDeleteDoesNotDispatch`, `cancelledSceneRecallDoesNotDispatch`, and `cancelledFactoryResetDoesNotDispatch` in Tasks 5, 7, 8, and 9.
- Demo/disconnected/version-mismatch states → persistent DEMO label and no real-connected claim; pin in Tasks 3 and 9.
- Narrow viewport, touch, and keyboard use → every module remains reachable without unusable overflow; pin with `keepsAllViewsReachableAtPhoneViewport`, `rendersTouchTargetsAtTabletViewport`, and `supportsKeyboardNavigationForCriticalControls` in Task 10.

## Scope Check

Use one plan: the feature views are separate modules over one shared mixer snapshot and adapter. The local hardware bridge is explicitly a later phase and gets its own spec after a physical T2208 is available.

## File Map

- `src/domain/`: mixer snapshot, capability profile, actions, validation, and demo seed data.
- `src/adapters/`: `MixerAdapter` interface and `DemoAdapter`; no network implementation in Phase 1.
- `src/app/`: adapter provider, `useMixer`, navigation, and responsive app shell.
- `src/components/`: reusable fader, meter, channel selector, status banner, and confirmation dialog.
- `src/features/`: one view/module each for mixer, meters/RTA, processing, routing, digital I/O, AutoMix, presets/scenes, system, and simulated connection.
- `src/i18n/`: `pt-BR` default plus `en` and `zh-CN` strings sourced from the APK where available.
- `src/styles/`: theme tokens, global layout, and breakpoints.
- Each feature folder owns a colocated stylesheet (`mixer.css`, `meters.css`, `processing.css`, `routing.css`, `automix.css`, `presets.css`, `system.css`, or `connection.css`) so view layout stays with its module.
- `e2e/`: Playwright DEMO flows across representative viewports.

## Task 2: Define the mixer model and simulated adapter

**Files:**
- Create: `src/domain/mixer-model.ts`, `src/domain/mixer-actions.ts`, `src/domain/demo-seed.ts`
- Create: `src/adapters/mixer-adapter.ts`, `src/adapters/demo-adapter.ts`
- Test: `src/adapters/demo-adapter.test.ts`, `src/domain/mixer-model.test.ts`

**Interfaces:**
- `MixerAdapter.getSnapshot(): MixerSnapshot`
- `MixerAdapter.subscribe(listener: (snapshot: MixerSnapshot) => void): () => void`
- `MixerAdapter.dispatch(action: MixerAction): Promise<DispatchResult>`
- `StorageLike` is `{ getItem(key: string): string | null; setItem(key: string, value: string): void }`.
- `new DemoAdapter(options?: { storage?: StorageLike; capabilities?: DeviceCapabilities })` injects deterministic storage and capability profiles for tests.

`MixerSnapshot` contains `mode: "demo"`, `demoConnection: DemoConnectionState`, `capabilities: DeviceCapabilities`, `channels: ChannelState[]`, `channelMap: ChannelMapEntry[]`, `buses: BusState[]`, `mainOutput: MainOutputState`, `dcaGroups: DcaGroupState[]`, `autoMix: AutoMixState`, `library: DemoLibrary`, `system: DemoSystemSettings`, and `selectedChannelId: string`. `DemoConnectionState` is `demo-idle | demo-discovering | demo-connecting | demo-connected | demo-disconnected | demo-firmware-model-mismatch | demo-bridge-unavailable`; every literal starts with `demo-`, and `DemoAdapter` never emits a real `connected` or `online` state. `DeviceCapabilities` has configurable numeric `channelCount`, `auxCount`, `fxSendCount`, and `dcaGroupCount`, `digitalCard: "unknown" | "present" | "absent"`, and `verified: boolean` (false for the initial static profile). `DispatchResult` is `{ ok: boolean; simulated: true; code: "applied" | "invalid" | "not-supported"; message?: string }`.

`MixerAction` is a discriminated union with these payload types: `channel.set` (`channelId: string`, control `fader|gain|mute|solo|pan|polarity|phantom48v`, `value: number|boolean`); `channel.rename` (`channelId: string`, `name: string`); `channel.map` (`channelId: string`, `inputId: string`); `mainOutput.set` (control `fader|mute`, `value: number|boolean`); `processing.set` (`channelId: string`, section `peq|geq|gate|compressor|fx|delay`, `controlKey: string`, `value: number|boolean|string`); `routing.setSend` (`channelId: string`, `busId: string`, `sendKind: aux|fx`, `level: number`); `routing.setPrePost` (`channelId: string`, `busId: string`, `position: pre|post`); `routing.setOutput` (`sourceId: string`, `destinationId: string`, `enabled: boolean`); `dca.assign` (`channelId: string`, `dcaGroupId: string`, `assigned: boolean`); `dca.set` (`dcaGroupId: string`, control `gain|mute`, `value: number|boolean`); `dca.link` (`dcaGroupIds: string[]`, `linked: boolean`); `automix.setActive` (`active: boolean`); `automix.setParticipation` (`channelId: string`, `enabled: boolean`); `automix.clear`; `library.save` (`kind: preset|scene`, `name: string`); `library.load`/`library.delete` (`itemId: string`); `library.copy` (`itemId: string`, `name: string`); `scene.recall` (`sceneId: string`); `system.set` (`setting: deviceName|deviceId|brightness|defaultPage|language|ip|shortcut`, `value: string|number`); `system.resetDefaults` (`scope: all|system`); and `demo.setConnectionScenario` (`state: DemoConnectionState`). Processing/system values are validated by the demo parameter table, not by assumed hardware ranges.

- [ ] **Step 1: Write model and adapter tests.** Cover the default simulated profile (30 channel slots, 8 Aux sends, 2 FX sends, 6 DCA groups, `digitalCard: unknown`, `verified: false`), `adaptsToInjectedCapabilities`, channel control updates, listener notification, valid library reload, `usesSeedWhenStoredLibraryIsAbsent`, and `fallsBackToSeedWhenStoredLibraryIsInvalid`.
- [ ] **Step 2: Run the targeted tests to verify they fail.** Run `npm run test -- --run src/adapters/demo-adapter.test.ts src/domain/mixer-model.test.ts`. Expected: FAIL because the model and adapter are missing.
- [ ] **Step 3: Implement the model and action union.** Use stable string IDs for channels, buses, DCA groups, presets, and scenes; represent 48V and other booleans explicitly.
- [ ] **Step 4: Implement `DemoAdapter`.** Seed a labelled demo state, apply only local actions, publish immutable snapshots, and persist only the preset/scene library using key `t2208-demo-library-v1`. Invalid JSON or unsupported schema must fall back to a valid seed and return a visible non-fatal result.
- [ ] **Step 5: Verify domain behavior.** Run the targeted tests; expected: PASS, including the malformed-library and configurable-count tests.
- [ ] **Step 6: Commit.** `git add src/domain src/adapters && git commit -m "feat: add T2208 demo state adapter"`.
